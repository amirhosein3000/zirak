# Spot trading (private: `x-api-key` with trade permission)

Zirak calls these **only** when every live-trading condition holds (`exchange/guard.py`). Sources:
`raw/spot/*.txt`. The spot swagger / service pages are **missing**, so status enums and error bodies are
`UNVERIFIED`.

## Order types (`raw/spot/order-types.txt`)
| Type | Behaviour |
|---|---|
| `LIMIT` | rests in the book at your price |
| `MARKET` | fills immediately against the book, possibly at several prices. **It's canceled automatically if it is larger than the book or would move the price more than 2 % from the last trade.** |
| `STOP_LIMIT` | becomes a LIMIT when the last trade crosses `stopPrice` (direction set by stop vs last price at creation) |
| `STOP_MARKET` | becomes a MARKET when the stop condition triggers |

Zirak uses LIMIT and MARKET only. Stops are enforced by its own RiskManager.

## Place order — `POST /v1/account/orders` (`raw/spot/place-order.txt`)
Body (JSON, **all values as strings**):
| Field | Required | Values |
|---|---|---|
| `symbol` | yes | e.g. `BTCUSDT` |
| `side` | yes | `"BUY"` / `"SELL"` |
| `type` | yes | `"LIMIT"` / `"MARKET"` / `"STOP_LIMIT"` / `"STOP_MARKET"` |
| `quantity` | yes | decimal string |
| `price` | yes (as documented, even for MARKET; `UNVERIFIED` whether MARKET ignores it) | decimal string |
| `stop_Price` | only for STOP_* (must not be sent otherwise) | decimal string |
| `client_id` | no | `[A-Za-z0-9_]`, must be unique. Generated by the server if omitted |

Success: HTTP **201**. `result` = order object (below). **Rate limit: 20 requests / 10 s.**

## Order object (shared by place / cancel / details / lists)
`clientOrderId`, `symbol`, `type`, `side`, `price`, `origQty`, `executedQty`, `executedSum`,
`executedPrice` (average), `executedPercent`, `fee`, `status` (examples: `NEW`, `FILLED`, `CANCELED`; full list
UNVERIFIED), `active` (bool), `stopPrice`, `stopPriceCondition`, `sum`, `transactTime`, `created_at`,
`updated_at`, `fills[]`.

`fills[]`: `{price, quantity, sum, fee, feeAsset, feeCoefficient, makerFeeCoefficient,
takerFeeCoefficient, isBuyer, symbol, timestamp}`, so the **fee asset is explicit per fill**.

## Cancel order — `DELETE /v1/account/orders/{clientOrderId}` (`raw/spot/cancel-order.txt`)
Works while the order is not `FINISHED` (fully filled). Returns the order object.

## Order details — `GET /v1/account/orders/{clientOrderId}` (`raw/spot/order-details.txt`)
Returns the order object. Zirak polls this to track fills (the private WebSocket needs a browser cookie).

## All orders — `GET /v1/account/orders` (`raw/spot/list-orders.txt`)
Query (all optional): `from`, `to` (date `2024-10-01`), `page`, `per_page`, `type`, `side`, `market`.

## Open orders — `GET /v1/account/openOrders` (`raw/spot/open-orders.txt`)
Query (optional): `symbol`, `page`, `per_page`. Used by the kill switch to cancel everything.

**Response shape UNVERIFIED:** the documented example shows `result: {"additionalProp1": [order, ...],
...}`, a swagger placeholder for a map. Zirak accepts either a list, a map of lists, or `{orders: [...]}`
and flattens it.
